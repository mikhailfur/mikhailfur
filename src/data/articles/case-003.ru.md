README часто становится **первым и единственным экраном** проекта для нового человека. Он должен быстро отвечать на три вопроса: что это, для кого это и как получить первый результат.

Полезная документация не пытается рассказать всё сразу. Сначала нужен короткий сценарий запуска, затем примеры и только после этого детали конфигурации. Такой порядок **уважает время читателя**.

Хороший README полезен и автору: он показывает, где проект нельзя объяснить одной фразой, а значит где интерфейс, название или структура требуют ещё одной итерации.
