The README often becomes **the first and only screen** of a project for a new person. It should quickly answer three questions: what is this, who is it for, and how to get the first result.

Useful documentation does not try to tell everything at once. First, a short launch scenario is needed, then examples, and only after that the configuration details. This order **respects the reader's time**.

A good README is also useful for the author: it shows where the project cannot be explained in one phrase, meaning where the interface, name, or structure requires another iteration.
